# Paper reading

目标是**准确提取**，不是写出漂亮的综述。

## 硬性约束

**不要凭记忆补全文献信息。** 标题、作者、年份、卷期、页码、数值结果，凡是论文里没读到或无法核实的，标注"未核实"，不要编。

幻觉引用是学术界当前最受关注的问题之一——被引文献并不支持所引论点的情况已有大规模实证。宁缺勿假。

## 阅读顺序

1. 标题、摘要、结论 —— 先确定它声称做了什么
2. 图与算法框 —— 论文的核心通常在这里，而不在正文
3. 方法节
4. 实验与消融 —— 重点看 baseline 选择和指标定义
5. 局限（Limitations）—— 作者自己承认的边界
6. 相关工作 —— 用来定位它在领域里的位置

## 提取什么

**它声称的贡献**
- 一句话说清"做了什么、比谁好、在什么条件下"
- 区分"新方法"、"新分析"、"新数据集"

**方法关键点**
- 输入/输出定义
- 核心机制（伪代码级）
- 关键超参与其敏感性
- 隐含假设（作者可能没明说的）

**实验设计**
- 数据集、规模、划分方式
- baseline 是否公平（同参数量？同训练量？同数据？）
- 指标定义与优化目标是否一致
- 有没有随机种子、多次运行、方差报告

**可复现性**
- 代码/权重是否公开
- 超参、数据预处理是否足够完整
- 是否依赖未公开数据或私有服务
- 是否有第三方独立复现

## 方法摘要的写法

用伪代码而不是散文：

```
输入: <张量/数据结构形状与含义>
重复 <次数>:
    <步骤1>
    <步骤2>
输出: <形状与含义>
关键超参: <名称 = 值/范围>, 对 <什么> 敏感
```

## 评估与批评

- **区分作者声称与证据支持**。两者经常不等。
- 指出实验设置中无法排除的其他解释。
- 标注只在单一 benchmark 上成立的结论。
- 注意"改进来自方法还是来自更多算力/数据"这类混淆。

## 输出格式

```
标题 / 出处        : <如未核实请标注>
一句话贡献         : <声称做了什么、比谁好、什么条件下>
方法核心           : <伪代码或机制要点>
关键假设           : <明说与未明说的>
实验设置           : <数据/规模/baseline/指标>
证据强度           : 强 / 中 / 弱，理由
局限               : <作者自陈 + 自己发现的>
可复现性           : <代码? 数据? 超参完整度?>
与我工作的关联     : <能用什么、不能用什么>
未核实             : <哪些信息没有确认>
```

## 多篇比较时

用统一维度对齐（方法类别、数据规模、指标、算力），不要逐篇重复段落。并明确说明**哪些结论是跨论文可直接比较的、哪些因为设置不同不可直接比较**。

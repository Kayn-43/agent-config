# Experiment review

目标是回答一个具体问题：**这组数据支持这个结论吗？**

## 先分离三件事

1. **观察**：实际跑出来的数字是什么
2. **推断**：作者/用户认为这说明了什么
3. **结论**：可以合理主张什么

三者经常不一致。多数实验问题出在第 2 步——把观察直接当成结论。

## 检查项

### 基线是否公平

- 参数量、训练步数、数据量是否可比
- 是否与调过参的基线对比、自己却没调参
- baseline 是官方实现还是复现（复现常偏低，会虚高自己的改进）
- 是否漏掉了某个明显更强的基线

### 控制变量

- 一次只改一个因素吗
- 消融是否覆盖了主要设计选择，还是只挑了有利的
- 改动 A 和 B 同时生效时，归因给谁

### 指标

- 指标定义与目标是否一致（例如优化 F1 却按 accuracy 汇报）
- 是否只报最好的那个指标
- 平均值是否带方差/置信区间；单次运行还是多次
- 测试集有没有在调参过程中被反复使用（信息泄漏）

### 显著性

- 差异与随机波动相比是否可观
- 有没有种子方差的报告
- 小样本上的"提升"通常不可靠

### 结论与证据的匹配

- 结论是否超出实验覆盖范围（只在 benchmark A 上试过，却声称通用）
- 是否把相关当成因果
- 是否把"没观察到差异"表述成"证明没有差异"

## 常见红牌

- 报告了 loss 下降但没有验证集曲线
- 只给最终数字，不给训练过程
- 用不同随机种子比较不同方法
- 关键数字在正文、表格、摘要里不一致
- 复现步骤缺失到无法判断是否跑对了
- 结果"好得不合理"（先怀疑设置错误，再怀疑泄漏）

## 输出格式

```
可以支持的主张   : <证据确实支撑的部分>
不支持的主张     : <超出证据的部分，说明缺什么>
未受控的变量     : <列出>
指标问题         : <定义/汇报口径的问题>
统计性问题       : <方差、样本量、种子>
需要补充的实验   : <按性价比排序，优先能证伪的>
结论可信度       : 高 / 中 / 低，理由
```

## 态度

- **主动找反例**，不要帮用户论证他的结论。
- 不确定时给出"能证伪它的最小实验"，而不是笼统地要更多数据。
- 数字有出入时，以**实际日志**为准，不要采信转述。
- 明确指出哪些判断是基于不完整信息做出的。
